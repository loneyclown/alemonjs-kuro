# 鸣潮助手 · alemonjs-kuro

基于 AlemonJS 的鸣潮机器人插件，提供库街区登录、实时便笺、角色练度与面板、探索度及游戏资讯查询。当前主要联调平台为 **QQ 官方机器人**，游戏数据来自库街区接口。

帮助页、练度总览、角色面板、体力便笺与探索度已重构；其余页面继续逐步优化。

## 安装到已有机器人

在 ALX 或其他支持 Git 应用的 AlemonJS 宿主中，填写：

| 项目          | 值                                                |
| ------------- | ------------------------------------------------- |
| 仓库          | `https://github.com/loneyclown/alemonjs-kuro.git` |
| 分支          | `release`                                         |
| 应用名        | `alemonjs-kuro`                                   |
| AlemonJS 宿主 | `^2.1.124`                                        |

`release` 是包含 `lib/` 和静态资源的可安装产物分支，`main` 用于源码开发。安装后在宿主启用应用，并使用宿主的 QQ、Redis 和截图浏览器配置。

通过包管理器安装时，在宿主机器人目录执行：

```sh
npm install "git+https://github.com/loneyclown/alemonjs-kuro.git#release"
```

如果宿主没有通过插件管理器自动启用应用，可在其 `alemon.config.yaml` 中合并：

```yaml
apps:
  alemonjs-kuro:
    enabled: true
    order: 10
```

保留宿主已有配置，重启后发送 `#mc帮助` 检查入口。

在 ALX 中打开「背包 → alemonjs-kuro → 配置」，可填写登录地址、监听地址和端口，也可开启可点击 Markdown 帮助。保存后重启机器人。图片帮助是默认设置。使用网页登录前，请填写浏览器可访问的地址。

手动配置时使用宿主的 `alemon.config.yaml`，插件字段位于 `alemonjs-kuro.login` 和 `alemonjs-kuro.markdown`。QQ 机器人凭据、Redis 和截图浏览器仍在宿主中配置。

**使用账号查询功能前，还需要完成[登录页部署](#登录页部署)。** 安装成功和帮助能发图，不代表手机已经能访问登录页。请按机器人实际运行的环境完成配置。

## 独立启动与本地开发

本机已在 Node.js **26.13.1**、Yarn **1.22.22**、AlemonJS **2.1.124** 下验证安装、构建和回归测试。图片渲染需要可用的 Chrome / Chromium / Edge，账号绑定和登录凭据需要 Redis。

```sh
git clone --branch main https://github.com/loneyclown/alemonjs-kuro.git
cd alemonjs-kuro
npm install -g yarn@1.22.22
yarn install
cp config.example.yaml alemon.config.yaml
```

编辑 `alemon.config.yaml`，填写自己的 QQ 应用和 Redis 配置。最小示例：

```yaml
login: qq-bot

qq-bot:
  app_id: '你的 QQ 机器人 AppID'
  secret: '你的 QQ 机器人 AppSecret'
  markdownToText: true

db:
  redis:
    host: '127.0.0.1'
    port: 6379
    db: 0
    password: ''

alemonjs-kuro:
  markdown:
    enabled: false
  login:
    host: '0.0.0.0'
    port: 8130
    # 必填：用户可访问的 IP 或域名；这里是局域网调试示例
    publicUrl: 'http://192.168.1.100:8130'
```

启动 Redis，确认 QQ 应用已具备所需消息权限，再执行：

```sh
yarn run dev
```

这个命令会独立启动机器人，不需要同时运行另一个宿主。接入已有宿主时，由宿主启动插件即可。

`alemon.config.yaml`、本地日志和构建产物已加入 Git 忽略规则。请勿把真实 AppSecret、验证码、Token 或专属登录链接提交到仓库。

## 登录与账号管理

1. 私聊机器人发送 `#mc登录`。
2. 在电脑打开消息中的链接，或用手机扫描二维码。
3. 输入手机号，完成滑块验证，获取并提交短信验证码。
4. 收到登录成功提示后，发送 `#mc查看`、`#mc体力` 或 `#mc练度`。

登录成功会绑定并激活该游戏账号。专属链接 **3 分钟有效**，重新获取会使旧链接失效；机器人重启后也需要重新获取链接。

登录页在第一次请求时启动，默认监听 `0.0.0.0:8130`。必须设置 `alemonjs-kuro.login.publicUrl` 为用户可访问的地址；未配置时会给出配置提示，不会自动使用容器内网 IP。`127.0.0.1` 或 `localhost` 只能在服务器本机访问，不能供手机或远程用户登录。

不知道地址该填什么时，按下方[登录页部署](#登录页部署)选择自己的部署场景。`publicUrl` 只填写协议、主机和端口，不附加 `/kuro/login/` 等路径。修改后重启机器人。

登录指令会先发送可直接打开的链接，再生成二维码。其他指令超过 2 秒未完成时，会发送一次处理中的提示；快速完成的指令不额外发送提示。

| 指令                         | 用途                         |
| ---------------------------- | ---------------------------- |
| `#mc查看`                    | 查看本人已绑定账号及当前账号 |
| `#mc绑定 123456789`          | 绑定 9 位特征码              |
| `#mc切换 123456789`          | 切换当前账号                 |
| `#mc解绑 123456789`          | 解绑本人账号                 |
| `#mc添加token <Token>,<DID>` | 私聊手动添加当前账号凭据     |
| `#mc删除token 123456789`     | 私聊删除本人指定账号凭据     |

也兼容私聊发送 `#mc登录 手机号 验证码`。通常直接使用网页登录即可。

凭据按 AlemonJS 的 `UserKey + UID` 隔离；仅绑定别人的 UID 不会获得其查询权限。旧版共享凭据不会自动迁移，升级后如提示无凭据，请重新登录。

## 登录页部署

网页登录需要让用户的浏览器连接到机器人。插件能够启动登录服务，但不能替你修改云平台安全组、Docker 端口或家用路由器。自动查询公网 IP 也只能得到地址，无法让端口自动可达，因此本项目不把“猜测一个 IP”当作完成配置。

以下步骤面向安装本插件的你，选择与机器人运行环境对应的一种方式即可。

### 先选择场景

| 机器人运行在哪里           | 谁打开登录页          | 应当选择的方式                                            |
| -------------------------- | --------------------- | --------------------------------------------------------- |
| 自己的电脑                 | 只在同一台电脑上打开  | 本机调试                                                  |
| 自己的电脑                 | 同一个 Wi-Fi 下的手机 | 局域网调试                                                |
| 云服务器，直接运行 Node    | 互联网上的用户        | 云服务器直连，或已有 HTTPS 域名                           |
| Docker / Docker 内的 ALX   | 互联网上的用户        | Docker 部署，再选择公网直连或域名                         |
| 家用电脑，没有可用公网入口 | 外网用户              | 需要自行配置公网入口或内网穿透，单改 `publicUrl` 无法解决 |

### 本机或局域网调试

在**宿主机器人目录**的 `alemon.config.yaml` 中合并以下配置。不要覆盖已有 QQ 和 Redis 配置；文件里已有 `alemonjs-kuro` 时，把 `login` 合并到同一个节点下。

```yaml
alemonjs-kuro:
  login:
    host: '0.0.0.0'
    port: 8130
    publicUrl: 'http://127.0.0.1:8130'
```

这个地址只供机器人所在电脑打开。要让同一局域网的手机扫码，在 Windows 终端执行 `ipconfig`，找到当前 Wi-Fi 或以太网网卡的 IPv4 地址，把 `127.0.0.1` 换成该地址，例如 `192.168.1.100`。手机应连接同一局域网，电脑防火墙需要允许 TCP 8130 入站。不要使用 Docker、WSL 或虚拟网卡的地址。

局域网地址不能提供给外网用户使用。

### 云服务器直接运行机器人

1. 在云服务器控制台找到这台服务器的**公网 IP**。
2. 按上面的 YAML 配置，保留 `host: '0.0.0.0'` 和 `port: 8130`，把 `publicUrl` 改为 `http://你的公网IP:8130`。
3. 在该服务器的安全组添加入站规则：协议 **TCP**，端口 **8130**。供任意外网用户使用时，IPv4 来源为 `0.0.0.0/0`；仅自己调试时可以限制为自己的公网 IP。
4. 如果服务器操作系统另有防火墙，也要允许 TCP 8130 入站。
5. 重启机器人，私聊发送 `#mc登录`，在手机移动网络下打开**新生成的链接**。

公网直连的 HTTP 地址可用于连通性排查；面向公共用户的长期部署推荐使用下方的 HTTPS 域名方案。

### Docker / Docker 内的 ALX

Docker 中的 `172.20.0.2` 等地址通常只在容器网络内可用。`publicUrl` 要填**宿主服务器的公网 IP 或域名**，不能填容器 IP。

除上述云服务器步骤外，还需要在**实际运行机器人进程的容器**发布端口。如果机器人是由容器内的 ALX 启动，就在该 ALX 容器配置端口；无需另建一个鸣潮助手容器。

Docker Compose 示例片段（合并到现有服务，保留原有端口、环境变量和数据卷）：

```yaml
services:
  alx: # 替换为你现有的服务名
    ports:
      # 原有端口继续保留
      - '8130:8130' # 左边是服务器端口，右边是插件监听端口
```

使用 `docker run` 部署时，对应的端口参数是 `-p 8130:8130`；不要仅凭这一个参数重建容器，要沿用原来的完整部署配置和数据卷。容器管理面板中通常对应“端口映射”：宿主端口 `8130`、容器端口 `8130`、协议 `TCP`。

Docker 端口变更通常需要按原部署方式重新创建容器，单纯 `docker restart` 不会添加映射。重新创建前确认机器人配置和 Redis 数据已持久化。完成后重启机器人，再发送 `#mc登录`。

如果宿主机的 8130 已占用，可以映射 `18130:8130`：插件 `port` 仍为 `8130`，`publicUrl` 使用 `http://你的公网IP:18130`，安全组和宿主机防火墙开放 **18130**。

### 已有 HTTPS 域名：推荐给公共机器人

已有域名和 HTTPS 网站时，可以复用网站入口，公网无需额外开放 8130；需要为登录服务添加反向代理设置。

1. 准备指向服务器的域名，例如 `login.example.com`，配置好 HTTPS 证书和网站入口。
2. 将 `publicUrl` 设置为 `https://login.example.com`。机器人仍在内部监听 8130。
3. 在该域名现有的 Nginx HTTPS `server` 中添加：

```nginx
location /kuro/login/ {
    proxy_pass http://127.0.0.1:8130;
    proxy_set_header Host $host;
    access_log off; # 登录 URL 含临时凭证，不写入此路径的访问日志
}
```

`proxy_pass` 末尾不要加 `/`，这样 `/kuro/login/...` 会原样转发；该路径的 GET 和 POST 都需要放行。用 `nginx -t` 检查配置通过后，按原网站管理方式重载 Nginx。

上例假设 Nginx 与机器人运行在同一宿主机。机器人在 Docker、Nginx 在宿主机时，可将容器端口仅发布到本机：`127.0.0.1:8130:8130`。如果 Nginx 也在另一个容器中，`127.0.0.1` 指的是 Nginx 自己，应使用同一 Docker 网络里的机器人服务名和容器端口，例如 `http://alx:8130`。

不要直接把 ALX 管理页面地址（例如工作台的 17390 端口）填入 `publicUrl`。本插件目前使用独立登录服务，工作台可访问不代表它已经代理了 `/kuro/login/`。

### 配好后怎么确认

1. 重启机器人后，私聊发送 `#mc登录`；登录服务会在第一次请求时启动。
2. 检查消息中的地址是自己配置的公网 IP 或域名。
3. 用手机**关闭 Wi-Fi，切到移动网络**，打开消息里的链接。可以看到手机号和滑块页面，才算外网连通。
4. 如果超过 3 分钟，重新发送 `#mc登录` 获取新链接。

| 看到的情况                                        | 应如何处理                                                 |
| ------------------------------------------------- | ---------------------------------------------------------- |
| 提示未配置 `publicUrl`                            | 检查宿主 `alemon.config.yaml` 中的配置层级，修改后重启     |
| 链接仍是 `172.20.0.2`、`192.168.x` 或 `127.0.0.1` | 公共部署不能使用容器、局域网或回环地址；改为公网 IP 或域名 |
| 连接超时                                          | 检查公网 IP、云安全组、系统防火墙和 Docker 端口映射        |
| 连接被拒绝                                        | 确认机器人已收到登录指令、登录服务启动无报错，且端口一致   |
| 能打开工作台，但登录链接打不开                    | 工作台和登录服务是不同入口，单独检查登录服务的映射和代理   |
| 域名返回 404 或 502                               | 检查反向代理是否保留完整路径、上游地址是否可达             |
| 提示链接已失效                                    | 重新私聊发送 `#mc登录`，不要复用过期、重启前或被替换的链接 |

没有公网入口时，可以自行选择内网穿透：将外部 HTTPS 地址转发到登录端口，再把该地址填入 `publicUrl`。本项目不自动安装穿透工具或依赖某个共享登录服务。

## 可点击 Markdown 帮助

默认使用图片帮助。QQ 机器人开通自定义 Markdown 消息权限后，在运行目录的配置中修改：

```yaml
alemonjs-kuro:
  markdown:
    enabled: true

qq-bot:
  markdownToText: false
```

重启后，`#mc帮助` 和 `#mc更多帮助` 会发送带可点击指令的 Markdown。带角色名、UID 或 Token 的指令先填入输入框，补齐参数后再发送；群聊点击行为取决于 QQ 客户端。登录和凭据操作仍只允许私聊。

Markdown 发送失败时回退图片；其他平台继续使用图片帮助。将 `enabled` 改回 `false` 即恢复图片模式。

## Expose 插件能力

插件启用后会自动注册 AlemonJS Expose，供同一运行实例中的社区插件发现和调用，无需指定调用插件或配置白名单。

- 协议：`kuro.waves`
- 默认提供者：`alemonjs-kuro`（以宿主实际加载的应用名为准）
- 契约版本：`1`
- 展示名称：`鸣潮助手`；入门指令：`#mc帮助`

| 动作          | 输入                      | 返回内容                               |
| ------------- | ------------------------- | -------------------------------------- |
| `help`        | `null`                    | 当前开放指令及私聊标记；无需用户上下文 |
| `accounts`    | `{}`                      | 当前聊天用户的绑定账号列表与激活账号   |
| `base`        | `{}`                      | 当前账号基础信息                       |
| `daily`       | `{}`                      | 资源、电台、周常与活动摘要             |
| `roles`       | `{}`                      | 当前账号角色列表与练度                 |
| `character`   | `{ "character": "今汐" }` | 指定角色属性、武器、技能和声骸词条     |
| `exploration` | `{}`                      | 地区、子区域及收集项目进度             |
| `tower`       | `{}`                      | 逆境深塔难度、区域与楼层星数           |

`base`、`daily`、`roles`、`character`、`exploration`、`tower` 可额外传入 9 位字符串 `uid`，但仅能查询当前用户本人已绑定且拥有凭据的账号；不传则使用当前激活账号。`accounts` 的 `activeUid` 为空字符串时表示没有可用的激活账号。

在调用插件的消息或交互处理链中执行，例如：

```ts
import { Expose } from 'alemonjs';

export async function readMyDaily() {
  const client = Expose.create();
  const provider = client.list('kuro.waves').find(item => item.name === 'alemonjs-kuro');

  if (!provider || provider.version !== '1') {
    throw new Error('鸣潮助手未加载或契约版本不匹配');
  }

  return client.call(
    'kuro.waves',
    provider.name,
    'daily',
    {},
    {
      timeoutMs: 30000
    }
  );
}
```

完整输入、输出契约可通过 `Expose.create().schema()` 获取。查询返回结构化 JSON，不发送聊天消息或启动截图。框架结果 `ok: true` 后，还需要检查业务结果的 `status`：`ok`、`not_bound`、`not_logged_in` 或 `error`；成功时数据位于 `result.data.data`。

账号身份来自框架当前事件的 `UserKey`，不接受调用方传入的 `UserKey`、Token 或其他凭据。账号动作要求真实的应用调用上下文及聊天用户上下文；后台任务没有聊天用户时返回 `FORBIDDEN`，不会猜测账号。帮助和能力发现仍可在无用户上下文时使用。

所有动作均标记为 `effect: 'read'`，有输入输出运行时校验，不产生写动作监听通知。超时、取消或卸载后会停止等待，并在后续请求前检查取消状态；已经发出的底层请求仍沿用现有 HTTP 超时。接口不开放登录、短信、凭据、绑定/解绑、签到或发送消息等操作。

## 构建与发布

日常修改在 `main`，安装与更新使用 `release`。源码中的版本字段不决定自动发布版本；`alemonc publish` 按已有正式 Git 标签计算下一个版本。

```sh
npm install -g alemonjs yarn@1.22.22

git add <本次要发布的文件>
git commit -m "描述本次修改"
alemonc publish --dry-run
alemonc publish
git push origin main
```

发布工具会从**当前源码 commit** 创建临时隔离空间、安装依赖、执行构建，按打包白名单生成产物，再原子推送 `release` 分支和 `vX.Y.Z` 标签。未提交、暂存中和未跟踪的修改都不会参加构建。

该命令发布到 **GitHub 分支与标签，不上传 npm，也不自动推送 main**。发布前完成检查和源码提交，发布后再推送源码。当前打包范围为 `lib/`、`package.json` 和 README；真实运行配置及日志不进入发布包。
